# Render에 말줍 배포하기

## 배포 전에 자료 백업

현재 사용하는 말줍의 데이터 관리에서 전체 백업을 다운로드합니다. localhost와 Render 주소는 다른 브라우저 저장소를 사용하므로 배포해도 기존 자료가 자동으로 나타나지 않습니다. 배포 후 새 사이트의 데이터 관리에서 백업을 복원하세요.

## Render 연결

1. https://dashboard.render.com 에 로그인합니다.
2. **New → Web Service**를 선택합니다. Static Site가 아닌 Web Service를 사용합니다.
3. GitHub를 연결하고 **Min8309/esl_101** 저장소를 선택합니다. 목록에 없다면 GitHub의 Render 앱 접근 권한에 해당 저장소를 추가합니다.
4. 이름은 원하는 이름(예: `maljup`), 브랜치는 **main**, Language/Runtime은 **Docker**로 설정합니다. Root Directory는 비워 두고 Dockerfile 경로는 **./Dockerfile**로 둡니다.
5. 제공되는 인스턴스 요금과 제한을 확인하고 선택합니다. Free가 표시되면 기능 확인에 사용할 수 있으나 유휴 정지와 자원 제한이 있을 수 있습니다. 운영 목적이라면 필요에 맞는 유료 인스턴스를 검토합니다.
6. Advanced의 **Health Check Path**를 **/healthz**로 설정합니다. 별도의 Build Command나 Start Command를 입력할 필요가 없습니다. Dockerfile이 설치와 실행을 담당합니다. PORT, Python 경로도 Dockerfile과 Render가 처리합니다.
7. **Create Web Service / Deploy Web Service**를 누릅니다. 첫 빌드는 Node.js·Python·자막 패키지를 설치하므로 시간이 걸립니다.
8. 상태가 **Live**가 되면 Render가 표시한 HTTPS 주소를 엽니다. 해당 주소 뒤에 `/healthz`를 붙였을 때 `{"status":"ok"}`가 나오면 서버가 응답하는 것입니다. 이 응답이 실제 YouTube 자막 접근 성공까지 보장하지는 않습니다.

## 배포 후 확인

- 로고, 모바일 메뉴, 카드 저장, 형광펜 수집이 정상인지 확인합니다.
- 공개 자막이 있는 유튜브 영상으로 가져오기를 확인합니다. YouTube가 데이터센터 IP를 차단하거나 제한하면 페이지는 열리더라도 자막 가져오기가 실패할 수 있습니다. 해당 오류를 확인해야 하며 배포 자체가 이를 해결하지는 않습니다.
- 모바일에서 HTTPS 주소로 접속하고 마이크 권한을 허용해 녹음을 확인합니다.
- 기존 JSON 백업을 새 주소에서 복원합니다. PC와 휴대폰의 브라우저 자료는 계속 별개입니다.
- Google Sheets를 사용한다면 Google Cloud의 웹 OAuth 클라이언트에 Render에서 발급된 실제 HTTPS 원본을 승인된 JavaScript 원본으로 추가합니다. 경로는 넣지 않습니다. 배포된 앱의 데이터 관리에서 클라이언트 ID를 다시 입력하고 연결합니다. 보안 비밀을 앱이나 저장소에 넣지 않습니다.

## 다음 업데이트

GitHub main에 새 커밋이 올라왔을 때 Render의 자동 배포 설정에 따라 배포되며, 자동 배포를 끈 경우 Manual Deploy에서 최신 커밋을 배포합니다. 코드 변경이 없는 일시적인 재시작은 별도의 설정 변경이 필요하지 않습니다.

## 로컬 Docker 확인

```sh
docker build -t maljup .
docker run --rm -p 3000:10000 maljup
```

브라우저에서 로컬 3000번 포트를 확인합니다. Dockerfile은 관리자 계정 대신 node 사용자로 서버를 실행하고, 웹에 필요한 파일만 이미지에 포함합니다. 데이터베이스 서비스나 API 키는 기본 배포에 필요하지 않습니다. 이 저장소에 배포 설정이 있다는 것과 Render 서비스가 실제 생성·배포됐다는 것은 다릅니다.

## Supadata 자막 API 연결 (Render의 YouTube 봇 확인 오류 대응)

1. [Supadata](https://supadata.ai)에서 계정을 만들고 대시보드에서 API 키를 발급합니다. 현재 요금·크레딧·이용 조건을 확인하세요. Google OAuth 클라이언트 ID와 다른 키입니다.
2. Render → **esl-101 서비스 → Environment → Add Environment Variable**에 아래 두 항목을 추가합니다.

   | Key | Value |
   | --- | --- |
   | `TRANSCRIPT_PROVIDER` | `supadata` |
   | `SUPADATA_API_KEY` | Supadata에서 발급한 실제 API 키 |

3. **Save, rebuild, and deploy** 또는 **Save and deploy**를 누르고 최신 커밋 배포가 **Live**인지 확인합니다. API 키를 GitHub, 브라우저 입력란, 채팅에 올리지 마세요.
4. 앱에서 `https://www.youtube.com/watch?v=5skWbChJy-8`를 입력하고 **스크립트 불러오기**를 누릅니다. 영어 자막을 선택하고 시간·문장이 나타나는지 확인합니다. 다른 영상·언어, 형광펜·수집도 확인하세요.

키가 있으면 기본적으로 Supadata를 사용합니다. `TRANSCRIPT_PROVIDER=supadata`를 명시하면 키 누락 시 설정 오류를 표시하며 차단된 로컬 추출기로 돌아가지 않습니다. `TRANSCRIPT_PROVIDER=local`이면 기존 Python 추출기를 사용합니다.

API는 `GET https://api.supadata.ai/v1/transcript`의 `mode=native`, `text=false`로 **기존 자막만** 요청합니다. 별도 AI 생성·번역을 요청하지 않습니다. 영상 주소와 선택 언어가 Supadata에 전달되고 API 이용량이 발생할 수 있습니다. 모든 영상의 성공을 보장하지 않습니다. 제공자가 자막 제작 방식을 알려주지 않으므로 자동/수동 여부를 표시하지 않으며, 추가 메타데이터 조회 비용을 피하기 위해 영상 제목 대신 영상 ID를 표시합니다.

### 앱의 사용량 보호 장치

추가 설정이 없어도 **서버 프로세스별 최근 24시간 5회, 최근 30일 80회, 최근 1분 10회**의 Supadata HTTP 호출 제한이 적용됩니다. 달력 날짜나 계정 결제 주기가 아닌 이동 시간 창입니다. 사용자별 한도가 아니므로 공개 앱을 이용하는 모든 사람이 함께 사용합니다.

- 호출 **전에** 횟수를 예약합니다. 실패, HTTP 206, 시간 초과도 되돌려 주지 않습니다. 비동기 작업의 상태 조회까지 매번 포함하므로 영상 5개를 보장하는 숫자가 아닙니다. 상태 조회 중 한도에 도달하면 조회를 중단하며, 제공자에서 이미 시작된 작업이나 과금이 취소되는 것은 아닙니다.
- 동일 영상·언어의 성공 결과는 최대 24시간, 최대 40개를 메모리에 보관합니다. 캐시 적중은 외부 요청 횟수를 쓰지 않고 한도에 도달해도 이용할 수 있습니다. 용량 초과 시 오래 들어온 항목이 빠지므로 항상 24시간 보관을 보장하지는 않습니다.
- 같은 영상·언어의 진행 중 요청은 로더에서 합칩니다. 서로 다른 작업은 로더에서 최대 2개이며, 기존 HTTP 진입점은 한 번에 1개의 가져오기만 허용합니다.
- 연결·응답 오류, 시간 초과, 자막 없음 등은 같은 영상·언어의 재시도를 10분간 막습니다(최대 100개 기억). 인증·크레딧·요청 한도 오류가 나면 새 요청을 1분간 멈춥니다. 자동 재시도나 다른 유료 제공자로의 자동 전환은 하지 않습니다.
- 제한 시 한국어 안내와 `Retry-After` 응답을 제공합니다. 이미 저장한 스크립트, 직접 붙여넣기와 자막 파일 가져오기는 계속 사용할 수 있습니다.

선택 환경 변수(서버 시작 시 반영):

| 변수 | 미설정 기본값 | 의미 |
| --- | --- | --- |
| `SUPADATA_DAILY_REQUEST_LIMIT` | `5` | 최근 24시간의 최대 외부 HTTP 호출 수 |
| `SUPADATA_30_DAY_REQUEST_LIMIT` | `80` | 최근 30일의 최대 외부 HTTP 호출 수 |

0~100000의 정수만 허용합니다. 빈 값이나 잘못된 값은 새 요청을 차단합니다. 어느 한 값을 `0`으로 설정하면 새로운 Supadata 호출이 중지됩니다. 이는 Supadata 경로에만 적용되며 Python 로컬 추출기는 변경하지 않습니다. 브라우저에서 이 값을 변경할 수 없습니다.

**이 보호 장치는 계정 전체의 크레딧·금액 상한이 아닙니다.** 영구 공유 저장소가 연결되어 있지 않아 재시작·재배포·프로세스 재생성 시 횟수, 대기 상태와 캐시가 초기화됩니다. 여러 인스턴스/프로세스는 각각 별도의 한도를 가지며 같은 API 키를 사용하는 다른 앱의 호출도 집계하지 않습니다. API 호출 횟수는 실제 청구 크레딧과 같다고 가정하지 않습니다. 과거 사용량 4크레딧이나 11월 23일 초기화일을 이 카운터의 초기 상태로 사용하지 않으며 배포 키와 확인된 계정의 일치도 검증되지 않았습니다. 인증 없는 공개 앱에서는 다른 사람이 한도를 소진할 수 있습니다.

계정 전체를 보호하려면 배포 키와 계정을 확인하고 제공자 측의 실제 사용량·결제·자동 충전 설정을 확인해야 합니다. 재시작과 여러 인스턴스를 통틀어 앱 한도를 유지하려면 영구 공유 저장소의 원자적 예약 및 장애 시 차단 정책을 추가해야 합니다. 확실한 중지가 필요하면 위 환경 변수 중 하나를 `0`으로 설정하고 실행 중인 모든 인스턴스에 반영하세요. Render 등 다른 서비스 비용은 이 설정으로 제한되지 않습니다.

### 이 변경을 서비스에 반영하는 절차

로컬 코드 수정만으로 운영 서비스에 적용되지 않습니다. 변경 검토와 푸시·배포 승인 후 GitHub에 반영하고 Render에서 해당 커밋을 배포해야 합니다. 환경 변수 미설정 시 위 기본값이 적용됩니다. 배포된 커밋과 모든 인스턴스의 설정을 확인한 뒤 `/healthz`와 앱 안내를 점검하세요. 실제 자막 가져오기 점검은 외부 사용량을 소모할 수 있습니다. 자동 배포가 켜져 있다면 main 푸시가 곧 배포를 유발할 수 있습니다.

오류 코드:

- `API_KEY_MISSING`: Render 키 설정 누락
- `API_AUTH_ERROR`: 키·계정 권한 확인
- `API_QUOTA_EXCEEDED` / `API_RATE_LIMITED`: 크레딧·요금제·요청 한도 확인
- `API_DAILY_LIMITED` / `API_PERIOD_LIMITED`: 앱의 최근 24시간 / 30일 한도
- `API_RETRY_COOLDOWN` / `API_SERVICE_PAUSED` / `API_BUSY`: 재시도 대기 / 서비스 일시 대기 / 동시 처리 제한
- `API_IMPORT_DISABLED` / `API_CONFIG_ERROR`: 관리자에 의한 새 요청 중지 / 제한 설정 오류
- `NO_CAPTIONS`: 해당 영상·선택 언어의 자막 미제공
- `API_NETWORK_ERROR` / `API_UPSTREAM_ERROR` / `API_TIMEOUT`: 네트워크·제공자 장애 또는 처리 지연
- `API_FORMAT_ERROR`: 시간 정보가 있는 응답 형식 확인 필요

API 키가 설정되지 않은 개발 환경에서는 모의 응답 테스트만 가능합니다. `/healthz` 성공은 API 키 유효성이나 실제 자막 가져오기 성공을 뜻하지 않습니다.

## 아이폰 웹 푸시 알림

웹 푸시에는 별도의 VAPID 키·영구 Disk·상시 실행 인스턴스 설정이 필요합니다. [아이폰 웹 푸시 설정 안내](iphone-push.md)를 따라 구성하세요. `/api/push/config`의 `enabled`로 서버 설정 여부를 확인할 수 있습니다. `/healthz`는 알림 준비 여부나 실제 휴대폰 수신을 검증하지 않습니다.
